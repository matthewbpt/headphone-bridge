# A Samsung Device is gated by its OS name, then confirmed by its extended status

The spec wants the Model identified without sending any writes, but a Galaxy Buds Device only reveals its device id (`EXTENDED_STATUS_UPDATED`, bytes 14–17) after the app sends the `MANAGER_INFO` handshake: in no capture does it send that status unprompted. So identification has two stages. First, the core only Attaches to a Device whose OS-reported identity points at the allowlist: the Samsung vendor service UUID is present and the name contains "Buds4 Pro". A Samsung Device with any other name is listed as unsupported and is never Attached, so it's sent nothing. Second, a name-matched Device is sent `MANAGER_INFO`, the one write allowed before identification. Samsung's own app sends the same handshake, and it changes no settings. If the device id in the reply isn't 359–361 (Galaxy Buds4 Pro), the core closes the link without any further write. The cost: a Buds4 Pro that the listener has renamed so the name no longer contains "Buds4 Pro" isn't Attached.
